# 字段说明

> 数据源：拉勾招聘公开岗位快照（社区整理）
> 文件：`data/raw/lagou_2024.csv`｜21,320 行 × 21 列｜24.9 MB｜抓取时点 2024-01-07

## 一、原始层字段（21 列）

| # | 字段 | 含义 | 实测情况 |
|---:|---|---|---|
| 1 | `id` | 数据集内部行号 | 21,320 个唯一值，纯自增序号，无业务含义 |
| 2 | `category` | 岗位二级分类 | 70 种，如「Java」「大数据开发工程师」 |
| 3 | `bigcategory` | 岗位一级分类 | 6 种：后端开发 / 运维 / 测试 / 前端开发 / 人工智能 / 移动开发 |

| 5 | `positionName` | 岗位名称 | 8,000+ 种写法，同义不同名严重 |
| 6 | `companyId` | 公司 ID | 6,771 个；可作公司维度主键 |
| 7 | `companyFullName` | 公司全称 | 最长 50 字符 |

| 9 | `industryField` | 所属行业 | **缺失 11.70%**，是空值率最高的字段 |
| 10 | `financeStage` | 融资阶段 | 缺失 0.91%；含脏值「不需要融資」（繁体）2 条 |
| 11 | `positionType` | 岗位类型 | 以「技术」类为主 |
| 12 | `createTime` | 岗位发布时间 | 2022-08-05 ~ 2024-01-07；**同一岗位的重复记录时间完全相同** |

## 二、派生字段（清洗层新增 4 列）

| 字段 | 类型 | 生成规则 |
|---|---|---|
| `salary_min` | int | 从 `salary` 正则提取下限 × 1000（单位：元/月）|
| `salary_max` | int | 从 `salary` 正则提取上限 × 1000 |
| `work_year_level` | int | 在校/应届=0、1年以下=1、1-3年=2、3-5年=3、5-10年=4、10年以上=5、不限=-1 |
| `education_level` | int | 不限=0、大专=1、本科=2、硕士=3、博士=4 |

入库时再加 `batch_date`（批次日期，来自 `create_at`，本项目取 2024-01-07），作为幂等键的一半。

## 三、清洗规则与业务理由

规则全部写在 `config/rules.py`，改规则不用改代码。

| 编号 | 规则 | 业务理由 |
|---|---|---|
| 001 | 丢弃 `positionDetail` | JD 正文对结构化指标无贡献，却占 79% 的存储；真要做 JD 文本分析回原始层另开链路 |
| 002 | 按 `positionId` 去重，保留 `createTime` + `create_at` 最新 | 同一岗位被重复抓取 6,584 次，不去重会让所有「岗位数」指标虚高 30.88% |
| 003 | 脏值归一（繁体→简体） | 「不需要融資」和「不需要融资」是同一个枚举值，不归一会让分组统计裂开 |
| 004 | 薪资正则解析 + 区间校验 | 统一成「元/月」数值才能算均值；剔除 <1,000 与 >500,000 的明显错误 |
| 005 | 经验/学历编码 | 文本档位无法排序和比较，编码成有序数值后才能算「经验要求分布」 |

## 四、已知质量问题（无法靠规则修掉，只靠校验发现）

1. **单时点快照**：`create_at` 全部是 2024-01-07，没有第二批次 → **不能做时间趋势分析**，任何「同比增长」类指标都不成立。
2. **岗位名同义异形**：`positionName` 有 8,000+ 种写法（「大数据开发工程师」195 条、「大数据开发」21 条、「高级大数据开发工程师」16 条），只能靠关键词映射分组，无法完全归一。
3. **合法范围内的异常值**：`NLP实习生 300k-400k`、`全栈工程师 1k-2k` 薪资单位/性质明显错，但都在合法区间内，规则拦不住 → 由 CHK-06 分布探查报警。
4. **行业缺失 11.70%**：`industryField` 近 2,500 行没有值，做行业维度分析时样本会偏。
5. **`positionType` 空值 1 条**：可忽略。

## 五、指标口径

统一约定（写在 `sql/02_metrics.sql` 顶部）：

- **统计批次**：`batch_date = (SELECT MAX(batch_date) FROM job_post)`，永远取最新批次。
- **岗位数**：`COUNT(*)`，一行 = 一个岗位（已按 positionId 去重）。
- **公司数**：`COUNT(DISTINCT company_id)`。
- **薪资**：取区间中点 `(salary_min + salary_max) / 2`，单位元/月。
- **薪资过滤**：`salary_min >= 1000`，排除 1k-2k 的实习/兼职/填错岗位。
- **岗位方向分组**：按 `position_name` 关键词，
  `大数据开发` → `数据开发|数据仓库|数仓|ETL` → `数据分析|BI` → 其他。
- **中位数**：MySQL 8 窗口函数手写（`ROW_NUMBER()` + `COUNT() OVER`），取 rn ∈ {FLOOR((n+1)/2), CEIL((n+1)/2)} 的均值。

## 六、行数口径（重要）

| 口径 | 数值 | 说明 |
|---|---:|---|
| 文件物理行数 | 238,919 | **不要用这个数**，`positionDetail` 里的换行被引号包着 |
| 逻辑记录数 | 21,320 | `len(pd.read_csv(...))` |
| 去重后岗位数 | 14,736 | 清洗层行数 = 数据库行数 |
